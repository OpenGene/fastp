# fastp benchmark corpus

Small, reproducible, license-free datasets for tracking fastp's throughput and
correctness across releases and thread counts. Each entry is a public accession
(verified against ENA) truncated to a fixed read-pair count so the corpus stays
small enough to run in CI or on a laptop, while still exercising a distinct code
path.

| id | source | reads used | why |
|---|---|---|---|
| `atac` | [SRR891268](https://www.ebi.ac.uk/ena/browser/view/SRR891268) — Buenrostro et al. 2013, GM12878, the original ATAC-seq paper | first 4,000,000 pairs | short inserts -> heavy Nextera adapter read-through; stresses `--detect_adapter_for_pe` |
| `wgs` | [SRR952827](https://www.ebi.ac.uk/ena/browser/view/SRR952827) — NA12878, NIST Genome in a Bottle reference material | first 4,000,000 pairs | plain 148bp WGS PE reads; the "typical" case with little adapter read-through |
| `synth` | generated by `scripts/gen_synth_pe.py` | 500,000 pairs | deterministic, no download required; same adapter-stress shape as `atac` but reproducible byte-for-byte without depending on ENA uptime |

`scripts/fetch_corpus.sh` downloads and truncates `atac` and `wgs` from ENA's
FTP mirror; `scripts/gen_synth_pe.py` generates `synth` locally. Neither
requires an SRA toolkit — plain `curl` + `gzip`.

## Extending this corpus

Datasets considered but not yet included (tracked here so effort isn't
duplicated): RNA-seq (poly-A read-through has a different quality-trimming
profile than DNA-seq), 10x-style single-cell (short-barcode R1 + cDNA R2,
relevant to fastp's UMI handling), and ancient-DNA-like short/degraded reads
(heavy quality trimming, high mismatch rate). Adding one is a matter of
picking a verified ENA/SRA accession and a truncation size in
`fetch_corpus.sh` — keep entries under ~500MB compressed so the whole corpus
stays runnable without a beefy machine.
